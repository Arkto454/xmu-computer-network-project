## 大厅与详情适配

- 当前前端是cursor/hasMore/nextCursor、每页4条、支持最新和最早排序；后端是page/size/total，固定createdAt降序、id降序，size默认20、范围1—100。适配层可请求size=4，内部维护页号并产生前端续页信息，不能把游标直接发给后端。真实模式只提供最新排序，不把单页倒序当全局最早排序。数据变化时页码式翻页可能漂移，保留去重/刷新但不承诺快照一致性。
- 后端只列WAITING且未过期任务；到期立即从大厅过滤，owner详情计算EXPIRED但不写回数据库。不要宣称后台定时过期已经实现。
- 摘要无联系方式/私密说明，详情有ownedByMe和可选privateInfo，**不返回**当前Mock模型的relation、allowedActions、runner、完整时间线或settlement。公开模型需字段白名单补显示值，不能编造历史/收益。后端已实现哪些操作应由显式能力开关控制，不能从状态枚举推导可提交接单/取消。
- 后端privateInfo为publisherPhone、publisherWechat、privateInstructions的扁平对象；前端需要privateInfo.owner.{phone,wechatId,note}。只转换后端实际返回字段，缺省时隐藏，不自行恢复或由公开publisherId补取联系方式。
- 发布者可看本人未结束任务的交接信息；其他学生的进行中详情无privateInfo。结束态只允许发布者看公开历史且隐藏私密，无关用户返回404。当前无接单者授权能力；未来参与者历史权限需新契约，不能套用Mock的完整runner流程。

## 登录、失败与退出

小程序wx.login取得临时code，POST给业务后端；AppSecret和code2Session仅在后端，session_key不下发。平台说明已再核对：临时code有效期5分钟，失败重试需新取code，不复用已消费code。

学生凭据默认1小时，同学生重登替换旧凭据，后端重启后失效；管理员凭据不能代替学生。现有前端会话仅内存，尚无expiresAt或重启恢复，S15需补真实会话验证与失效处理，继续保留账号代次/迟到401保护。后端没有刷新或退出接口；前端退出只能清本地会话，不宣称服务端立即撤销已签发凭据。

| 场景 | HTTP / code | 页面要求 |
| --- | --- | --- |
| 输入不合规 | 400 / INVALID_REQUEST | 就近反馈，不假设有逐字段错误结构 |
| code无效或已用 | 401 / WECHAT_LOGIN_FAILED | 提示重新登录，新取code；不当任务失败 |
| 受保护请求身份无效/禁用 | 401 / UNAUTHORIZED | 当前会话一次失效并回登录，旧账号响应不得清新账号 |
| 禁用账号登录 | 403 / ACCOUNT_DISABLED | 明确账号不可用，不编造禁用在途任务处理 |
| 微信配置缺失 | 503 / WECHAT_NOT_CONFIGURED | 显示环境尚未配置，不假装模拟成功 |
| 微信忙/连接失败 | 503 / WECHAT_UNAVAILABLE | 可手动新取code重试，不无限重发 |
| 详情不存在或不可看 | 404 / TASK_NOT_FOUND | 统一不可查看，清旧私密字段，不泄露隐藏历史 |

现有通用请求封装对非2xx主要按HTTP处理，S15应按已确认code细化展示并结合操作语义：微信登录失败不等于任务写结果待确认；发布的超时、网络或5xx仍不得误报确定失败。发布成功只有id/status，需随后查详情；成功后详情查询失败只能重试打开原编号，不能再发布。

**本版没有发布幂等键或结果找回接口**。可以联调正常发布路径，但丢失响应后的恢复仍是S16未通过项；不添加无效requestId、不自动重发、不以大厅相似标题判定自己的发布结果。
