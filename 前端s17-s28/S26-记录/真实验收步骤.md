# S26真实验收待办

需发布者A、接单者B及有权限的管理员。用可恢复的测试环境和明确虚构任务，手机需要可访问后端。此处仅为步骤，尚未执行，不包含任何凭据。

1. A发布、B接单并确认取件。双方按后端现有取消申请接口发起并同意，使申请进入AWAITING_REVIEW；当前小程序尚未提供这组协商取消页面，需后端/Apifox配合，不能把“未接单直接取消”当这一步。
2. 管理员审核通过该申请并填写测试原因。A/B分别刷新任务详情，核对已关闭、同一原因和审核时间，无交接私密信息、无业务按钮。关闭详情的辅助查询失败时仍应保留终态，重试后原因恢复。
3. 在原交付码页刷新/等待只读核对，确认旧图与刷新/停用按钮消失。原扫码页刷新后无核对和确认权限。构造关闭与交付确认竞争时只允许一个后端终态，客户端随后重新查询，不自动重发。
4. B刷新模拟收益，核对该关闭任务没有新增结算。不得只根据详情文案判定数据库账本通过。
5. 禁用测试账号须后端提供可恢复操作并明确授权，不能禁用本人唯一账号。验证既有凭据收到401后清会话并重登提示，新微信登录明确ACCOUNT_DISABLED时提示联系管理员；恢复后应能重新登录。

仍待后端补充：学生账号限制的范围/期限/原因字段及管理接口、是否允许完成在途任务的规则。当前源码是禁用后受保护请求统一拒绝，不能由前端自行放行或猜测限制类型。真实两账号及管理员关闭不要求新增小程序管理端。
